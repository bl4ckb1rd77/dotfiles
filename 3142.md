Bei den im Container identifizierten JAR-Dateien handelt es sich um reine statische Artefakte, die innerhalb von ZIP-Archiven abgelegt sind und vom Container ausschließlich über einen Nginx-Webserver via HTTP zur Verfügung gestellt werden. Da der Container auf einem Distroless-Basis-Image basiert und weder über eine Java-Laufzeitumgebung (JRE/JDK) noch über eine Shell, Interpreter oder sonstige ausführbare Binares verfügt, existiert im gesamten Container-Kontext keine ausführende Ebene. Selbst wenn ein in den ZIP-Archiven enthaltenes JAR-Paket theoretische Sicherheitslücken aufweist, können diese Mangels einer Ausführungsumgebung niemals aktiv getriggert oder interpretiert werden. Die Dateien verhalten sich innerhalb der Container-Infrastruktur wie reine passive Daten-Payloads ohne jegliches funktionales Risikopotenzial.
